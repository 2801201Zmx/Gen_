# gen

免端口配置的内网穿透工具（类 rathole），Go 编写，**零第三方依赖**，单二进制同时充当服务端与客户端。

> 本文件是中文文档；English version: [README_EN.md](./README_EN.md)

## 为什么用它

- **rathole**：控制通道（如 2333）之外，每个服务都要在配置里登记 `bind_addr` / `local_addr`，多一个服务就要改一次配置、重启一次；
- **gen**：通道端口（默认 2333）**只用来建立通道**。数据端口**不需要在工具里登记任何服务**——公网访问服务端的哪个端口，就按**原端口 1:1** 转发到客户端本机同端口。端口号全程不变。

```
curl 公网IP:80   ──▶  服务端监听 80  ── 控制通道 ──▶  客户端拨 127.0.0.1:80
curl 公网IP:443  ──▶  服务端监听 443 ── 控制通道 ──▶  客户端拨 127.0.0.1:443
```

## 快速开始

```bash
# 服务端（放在有公网 IP 的机器上）
./gen server -token 你的令牌          # 通道端口默认 2333，数据端口默认自动

# 客户端（放在内网机器上，只需 IP + token，不填任何端口）
./gen client -server 公网IP -token 你的令牌
```

客户端日志出现：

```
隧道已建立: 通道 1.2.3.4:2333，公网访问服务端任意端口将按原端口转发到 127.0.0.1 同端口
```

之后公网访问 `公网IP:80` 即到达客户端本机 `80` 端口。

**防火墙/安全组**：照常放行你要用的服务端口（如 80/443/22）和通道端口 2333 即可。

## 参数

### 服务端

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-token` | （必填） | 接入令牌；也可用环境变量 `GEN_TOKEN` |
| `-port` | `2333` | **通道端口**：仅用于客户端建立通道（可自定义） |
| `-ports` | `auto` | 数据端口范围。`auto` = 1-65535 排除系统临时端口段（Linux 读 `/proc/sys/net/ipv4/ip_local_port_range`，通常 32768-60999；Windows/macOS 排除 49152-65535）；也可显式指定，如 `-ports 1-65535` |
| `-bind` | `0.0.0.0` | 监听地址 |
| `-config` | 自动查找 | 配置文件路径（INI 格式，见下） |

### 客户端

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-server` | （必填） | 服务器 IP 或域名，可带 `:通道端口`（不带则默认 2333）；也可用环境变量 `GEN_SERVER` |
| `-token` | （必填） | 接入令牌；也可用环境变量 `GEN_TOKEN` |
| `-local-host` | `127.0.0.1` | 本地服务所在地址（端口与原端口一致，无需填写） |
| `-channels` | `4` | 并行数据通道数量（`0` = 退化单通道，`1-64`）。数据面拆到多条 TCP 流，总吞吐 ≈ 单流上限 × 通道数；旧服务端不支持时自动退化 |
| `-config` | 自动查找 | 配置文件路径（INI 格式，见下） |

### 配置文件（INI）

两端都可以把参数写进配置文件，命令行可以做到**零参数**。示例（客户端）：

```ini
[config]
remote_addr = "公网IP"        # 不写端口默认 2333；也可写 "公网IP:端口"
default_token = "你的令牌"
# local_host = "127.0.0.1"    # 可选
# channels = 4                # 可选：并行数据通道数量（0-64）
```

服务端：

```ini
[config]
default_token = "你的令牌"
# port = 2333                 # 通道端口，可选
# ports = "auto"              # 数据端口范围，可选
# bind = "0.0.0.0"            # 监听地址，可选
```

- 用 `-config 路径` 显式指定；不指定时自动查找 `./gen.ini`、`/etc/gen/gen.ini`；
- 支持 `#` / `;` 注释，值可以带引号；
- **优先级：命令行参数 > 配置文件 > 环境变量 > 默认值**。

### 环境变量

| 变量 | 用途 | 优先级 |
|------|------|--------|
| `GEN_TOKEN` | 令牌备用来源 | 低于 `-token` / 配置文件 |
| `GEN_SERVER` | 客户端服务器地址备用来源 | 低于 `-server` / 配置文件 |

## 工作原理

1. **建立通道**：客户端连接服务端通道端口（默认 2333），发送 `TOKEN <令牌>` 完成认证，
   形成一条控制通道。该端口上非握手的连接同样按数据端口处理（原端口转发）。
2. **并行数据通道（多通道）**：客户端认证成功后，再向通道端口建立 N 条（默认 4，`-channels` 可调，
   0 = 关闭）数据通道（`DATA <令牌> <序号>` 注册）。每个转发流被固定路由到其中一条通道，
   双向 `DATA/CLOSE` 帧只走该通道，`OPEN/PING/PONG/KICK` 仍走控制通道。
   数据面并行把单条 TCP 流的带宽上限拆掉：**总吞吐 ≈ 单流上限 × 通道数**，
   同时单条通道上的丢包重传不再拖累其他流。
3. **原端口 1:1 转发**：服务端在每个数据端口上监听。公网连接到达端口 N 时，
   服务端通过控制通道发送 `OPEN` 帧（携带端口号 N，以及所选数据通道序号）；
   客户端收到后拨号 `127.0.0.1:N`，双向转发数据。端口号全程不变，因此无需在工具里登记任何端口。
4. 帧协议 `OPEN / DATA / CLOSE / PING / PONG / KICK`；客户端每 30 秒心跳
   （控制通道 + 每条数据通道），服务端 90 秒无帧判失联；断线自动指数退避重连。
5. **通道自愈**：某条数据通道断开时，两端只清理该通道承载的流，客户端自动补建新通道，
   控制通道与其他通道不受影响。旧版服务端不支持数据通道时，客户端自动退化为单通道模式；
   旧版客户端连新服务端则完全不建立数据通道，双方均向后兼容。
6. **同一 token 同时只允许一个客户端**：新客户端顶替旧会话，旧客户端收到 `KICK` 通知后退出。
7. **端口冲突**：某个数据端口已被本机其他服务占用时，gen 静默跳过、不接管也不报错
   （端口归属保持系统原生行为，后续冲突由 Linux 自己报）；启动结束后只输出一行汇总
   “已占用端口 N 个（…）：归本机原服务所有”。通道端口被占用则直接以系统错误终止启动。

> 关于默认排除系统临时端口段：出站连接（DNS、系统更新、SSH 出去等）需要临时源端口。
> 若 gen 把 1-65535 全部绑定，服务端自身将无法发起任何出站连接。因此默认 `-ports auto`
> 自动排除系统的临时端口段，既覆盖所有常规服务端口（1-32767 + 61000-65535），
> 又不影响服务器自身联网。确有需要时可用 `-ports 1-65535` 显式全绑（接受该代价）。

## 构建

需要 Go 1.21+：

```bash
go build -o gen .
```

交叉编译到全平台：

```bash
./build.sh
```

产物：Linux / Windows / macOS × amd64 / arm64。服务端默认监听大量端口，
进程会自动把文件描述符软上限提升到硬上限（Linux），受限的环境可用 `-ports` 收窄范围。

## systemd 部署（Linux 服务器开机自启，网络就绪后再启动）

项目自带服务单元文件 `gen.service`（服务端）与 `gen-client.service`（客户端）。

```bash
# 1. 安装二进制（按机器架构选 amd64/arm64：uname -m 查看，x86_64→amd64，aarch64→arm64）
sudo install -m 755 gen-0.5.0-linux-amd64 /usr/local/bin/gen

# 2. 安装服务单元（服务端 gen.service；客户端机器用 gen-client.service）
sudo cp gen.service /etc/systemd/system/gen.service

# 3. 创建配置文件（0600 权限，令牌不出现在进程命令行里）
sudo mkdir -p /etc/gen
sudo tee /etc/gen/gen.ini <<'EOF'
[config]
default_token = "换成你的令牌"
EOF
sudo chmod 600 /etc/gen/gen.ini

# 4. 开机自启并立即启动
sudo systemctl daemon-reload
sudo systemctl enable --now gen
sudo systemctl status gen
```

服务单元要点：

- `Wants=network-online.target` + `After=network-online.target`：**开机后等网络服务就绪
  （DHCP/静态地址配置完成）再启动**；
- `Restart=always` + `RestartSec=5`：进程异常退出自动拉起；
- `LimitNOFILE=1048576`：放开文件描述符硬上限（默认要监听上万个端口）；
- 配置通过 `-config /etc/gen/gen.ini` 读取，不写在命令行里。

## 与 rathole 的对比

| | rathole | gen |
|---|---|---|
| 服务端口登记 | 每个服务写 `bind_addr` / `local_addr` | **零登记**，原端口 1:1 自动转发 |
| 安全组放行 | 每个服务端口手动添加 | 照常放行服务端口 + 通道端口即可 |
| 通道端口 | 控制通道（如 2333） | 2333（仅用于建立通道，可自定义） |
| 配置文件 | 服务端、客户端各一份 TOML | 可选 INI（`gen.ini`），命令行参数即可 |
| 多客户端 | 支持 | 同一 token 同时只允许一个（后连顶替先连） |
| 语言 | Rust | Go（无第三方依赖） |

## 安全说明

- token 与数据**明文传输**，请只在可信网络使用；公网生产环境建议外包一层
  TLS 或 WireGuard，或使用 rathole 的 TLS 模式。
- 拿到 token 即等于拿到你内网的全部端口：请使用高强度随机令牌，
  并建议在防火墙/安全组上把通道端口限制到可信来源 IP。
- gen 会尝试接管数据端口范围内所有空闲端口，请知悉（被占用的端口不受影响）。

## 已知限制

- 不做 TCP 半关闭（half-close）：一端 EOF 即整体关闭，HTTP 等协议无影响。
- 端口号必须 1:1 对应（公网 N → 客户端本机 N），不支持改端口号映射。
- 带宽天花板是「单条 TCP 流上限 × 通道数」：默认 4 条通道已远超常见链路；
  高延迟（>100ms）链路上要跑满大带宽时，调大 `-channels`（如 16）即可。
  系统级调优参考 `scripts/tuning.md`（TCP 窗口 + BBR）。

## 带宽调优

单条 TCP 流的上限 ≈ 窗口大小 ÷ 往返延迟。需要跑满大带宽时：

1. 两端把 TCP 窗口调大并启用 BBR（见 `scripts/tuning.md`，也可直接执行其中命令）；
2. 客户端加大 `-channels`（每个通道 = 一份独立窗口，总吞吐按通道数放大）；
3. 真正的天花板永远是链路本身（云带宽套餐 / 家庭宽带）。
